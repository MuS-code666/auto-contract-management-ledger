# ローカル契約書管理

スキャンした契約書PDFから、契約管理に必要な情報を **このPCの中だけで** 抽出し、利用者が確認・修正したうえで台帳に登録するアプリです。
PDFはカテゴリー別のフォルダに保存し、一覧検索・期限管理・Excel出力・バックアップができます。

- 契約情報を外部API・クラウドOCR・外部の生成AIへ送信しません。
- 画面はこのPCのブラウザで開くローカルWebアプリです（`127.0.0.1` のみで待ち受け）。
- OCRやLLMが無くても、PDFの取込み・手動入力・登録・検索・Excel出力は利用できます。
- 抽出結果は「候補」です。根拠ページ・原文と並べて表示し、利用者の確認を前提にしています。

操作方法は [docs/操作説明.md](docs/操作説明.md)、設計は [docs/設計.md](docs/設計.md)、検証結果は [docs/検証結果.md](docs/検証結果.md) を参照してください。

## 1. 動作環境

| 項目 | 内容 |
|---|---|
| OS | Windows 11（64bit）。Windows 10 は未確認 |
| CPU / メモリ | Intel Core i5 以上・16GB を想定（GPU不要） |
| Python | 3.12（64bit）推奨。3.11〜3.13 を許可（確認済みは 3.12.10） |
| ブラウザ | Microsoft Edge（Windows標準）。PDF表示はブラウザ内蔵のPDFビューアを使用 |
| ディスク | アプリ＋依存パッケージ 約700MB、ローカルLLMを使う場合は追加で約2.6GB |

処理時間はCPUによって大きく変わるため保証していません（参考値は [docs/検証結果.md](docs/検証結果.md)）。

## 2. セットアップ（初回のみ・インターネット接続が必要）

1. Python 3.12（64bit）を https://www.python.org/ からインストールします。インストール画面で **「Add python.exe to PATH」** にチェックを入れてください。
2. このフォルダの **`setup.bat`** をダブルクリックします。
   - `.venv` フォルダに仮想環境を作り、`requirements.txt` のパッケージ（OCRのモデル同梱）をダウンロードします。
   - 最後に「セットアップが完了しました」と表示されれば完了です。
3. （任意）自社名などの初期設定をファイルで用意する場合は、`config\settings.example.json` を `config\settings.json` にコピーして編集します（初回起動時だけ反映）。画面の「設定」からでも変更できます。

開発・テストを行う場合は `powershell -ExecutionPolicy Bypass -File scripts\setup.ps1 -Dev` を実行します（pytest とサンプル生成用 reportlab を追加導入）。

### 初回導入と通常利用の通信の区別

| 場面 | 通信 |
|---|---|
| `setup.bat`（初回） | PyPI から Python パッケージをダウンロード（RapidOCR のモデルはパッケージに同梱） |
| `setup_llm.bat`（任意・初回） | GitHub から llama.cpp、Hugging Face から LLMモデル（約2.5GB）をダウンロード |
| **通常利用（`start.bat`）** | **インターネット接続は不要。** アプリは `127.0.0.1` のみで待ち受け、LLMも `127.0.0.1` に限定 |

通常利用時に、モデルの自動ダウンロード・テレメトリ・更新確認は行いません（[6. セキュリティと外部送信](#6-セキュリティと外部送信) 参照）。

## 3. 起動と終了

- **起動:** `start.bat` をダブルクリック → 黒いウィンドウが開き、ブラウザで `http://127.0.0.1:8765/` が開きます。
- **終了:** 黒いウィンドウで `Ctrl+C` を押すか、ウィンドウを閉じます。
- ポートを変える場合: `start.bat --port 8800`。データフォルダを変える場合: `start.bat --data-dir D:\契約台帳データ`（または環境変数 `CONTRACT_LEDGER_DATA`）。

## 4. OCR・ローカルLLMの導入

### 4.1 OCR（既定：RapidOCR）

`setup.bat` で自動的に導入されます。追加作業は不要です。設定画面の「OCRの動作確認」で確認できます。

代替として **Tesseract** も使えます（縦書きの多い文書向け）:
1. https://github.com/UB-Mannheim/tesseract/wiki から Windows 用インストーラーを取得し、インストール時に「Additional language data」で **Japanese** と **Japanese (vertical)** を選択します（管理者権限が必要）。
2. 設定画面で OCRエンジンを「Tesseract」にし、`tesseract.exe` の場所（既定 `C:\Program Files\Tesseract-OCR\tesseract.exe`）を確認して「OCRの動作確認」を押します。

### 4.2 ローカルLLM（任意）

LLMを使うと、表現の揺れが大きい契約書でも候補を出しやすくなります。LLMが無い場合は、ルール抽出（正規表現）だけで動作します。

1. `setup_llm.bat` を実行します（llama.cpp CPU版と Qwen3-4B-Instruct-2507 Q4_K_M を `tools\` と `models\` にダウンロード。モデルの SHA-256 を照合）。
2. `start_llm.bat` を実行します（`127.0.0.1:8081` で LLM サーバーが起動。ウィンドウは開いたままにします）。
3. アプリの「設定」→「LLM」を **ローカルLLMサーバー（OpenAI互換）**、接続先 `http://127.0.0.1:8081/v1` にして保存し、「LLMの動作確認」を押します。

Ollama を使う場合は、接続先を `http://127.0.0.1:11434/v1`、モデル名を Ollama のモデル名にします（Ollama 自体の更新確認等の設定は Ollama 側で行ってください）。

LLM利用時の目安（未計測。CPUにより大きく変動）: メモリ約4〜5GB、1文書あたり数分程度。長い文書は約6,000文字ごとに分割して処理し、分割ごとの処理状況を記録します。

## 5. 採用した構成と選定理由

| 区分 | 採用 | 理由 | ライセンス |
|---|---|---|---|
| Webフレームワーク | FastAPI + Uvicorn | 軽量、Pythonだけで完結、型検証（pydantic） | MIT / BSD-3 |
| DB | SQLite（Python標準） | 1台1人利用に十分、ファイル1つで管理、バックアップAPIあり | Public Domain |
| PDF処理 | pypdfium2（PDFium） | 文字抽出とページ画像化。**PyMuPDF は AGPL のため不採用** | Apache-2.0 / BSD-3 |
| OCR（既定） | RapidOCR + PP-OCR（ONNX） + ONNX Runtime | 日本語を含む認識モデルが **pipパッケージに同梱** され管理者権限不要、CPUで1ページ約3秒（検証環境）、ネットワーク遮断下で動作確認済み | Apache-2.0 / Apache-2.0 / MIT |
| OCR（代替） | Tesseract 5（jpn / jpn_vert） | 縦書き対応、導入実績が多い。ただし導入に管理者権限が必要 | Apache-2.0 |
| LLM実行 | llama.cpp `llama-server` | CPUのみで動作、OpenAI互換API、JSONスキーマで出力形式を制約可能、テレメトリなし | MIT |
| LLMモデル | Qwen3-4B-Instruct-2507（Q4_K_M, 約2.5GB） | 日本語対応、16GBメモリで動作する規模、商用利用可能なライセンス | Apache-2.0 |
| Excel | openpyxl | .xlsx の書式（日付・列幅・フィルター・固定）を細かく設定可能 | MIT |
| 画面 | 素の HTML / CSS / JavaScript | CDN・外部フォント・ビルド工程が不要 | — |

OCRとLLMは交換可能なアダプター（`app/ocr/`、`app/llm/`）として分離しています。別のエンジンを追加する場合はアダプターを追加して設定で選びます。

## 6. セキュリティと外部送信

- Webサーバーは `127.0.0.1` のみで待ち受けます。Host ヘッダーを検査し（DNSリバインディング対策）、更新系APIには独自ヘッダーを必須にしています（他サイトからの書込み要求を拒否）。
- LLMの接続先URLは `127.0.0.1` / `localhost` / `::1` に限定し、それ以外は設定できません。HTTPクライアントはプロキシ環境変数を使いません。
- PDF本文は解析対象のデータとして扱います。LLMにはコマンド実行・ファイル操作・通信の手段を与えず、応答はJSONスキーマで検証し、**根拠原文が本文に実在しない値は「要確認」** にします。本文中の命令文（例：サンプル07の「システムへの指示」）には従いません。
- FastAPI 0.16x に内蔵された OpenTelemetry 計測はコードで無効化し、エクスポーターも自動設定しません（OpenTelemetry SDK は導入していません）。起動スクリプトでも `OTEL_SDK_DISABLED` 等を設定しています。
- RapidOCR はモデルファイルのパスを明示して使い、モデルが無い場合はダウンロードせず「利用不可」と表示します。
- 通常ログ（`data\logs\app.log`）には契約本文・当事者名・検索語を出力しません（ID・処理段階・件数のみ）。アクセスログは無効です。
- 画面に表示する契約書由来の文字列は、すべてテキストとして表示し HTML として解釈しません。

## 7. データの保存場所

既定ではこのフォルダの `data\` にすべて保存します（設定画面でPDF保存ルートは変更可能）。

```
data\
  ledger.db        台帳・設定・抽出結果・OCR結果・履歴（SQLite）
  契約書\          PDF保存ルート（既定）\<カテゴリー>\C000001_契約書名_相手方名.pdf
  imports\         取込み中（下書き）のPDFのコピー
  backups\         バックアップ（backup_日時.zip）
  logs\            ログ
```

## 8. テスト

```
test.bat                                         … 全テスト（モック・実OCRを含む、約10秒）
.venv\Scripts\python -m pytest -m real -v        … 実OCR・実LLMの検証だけ
set LEDGER_LLM_URL=http://127.0.0.1:8081/v1      … 実LLMの検証を有効にする場合（start_llm.bat 起動後）
.venv\Scripts\python scripts\evaluate.py --set all --ocr rapidocr                       … 抽出精度の評価（ルール＋OCR）
.venv\Scripts\python scripts\evaluate.py --set all --ocr rapidocr --llm openai_compat    … LLM込みの評価
```

テストには `samples\` の架空の契約書PDF（`scripts\make_samples.py`・`make_holdout.py` で生成）を使います。実在の会社・人物・機密情報は含みません。
**モックを使うテスト（`test_llm_mock.py` 等）の成功は、実際のモデルの抽出精度を示すものではありません。**

## 10. 既知の制約・未検証事項

**既知の制約**
- 初期版はPDF1件ずつの手動取込みです（フォルダ監視・一括処理なし）。Excelからの再取込みは対象外です。
- ルール抽出は「以下「甲」という」等の一般的な書き方を前提にしています。表形式の署名欄、縦書き、手書き、表の中の条件は取りこぼしやすく、その場合は要確認・未入力として表示されます。
- 通知期限の自動計算は「満了日の○日／○か月前」のような単純な条件だけです。営業日・休日、「前日まで」等の解釈は行いません（計算方法を画面に表示）。
- 登録済み契約の「再解析」はありません（取込み中の下書きでのみ再解析可能。手修正した項目は上書きしません）。
- RapidOCR の処理中は1ページの途中で中止できません（ページの区切りで中止します）。Tesseract はページ処理中でも中止できます。
- 押印・署名の真正性、契約の法的有効性は判定しません。

**未検証（この開発環境で確認できていないこと）**
- **実際のローカルLLMでの抽出精度・処理時間・メモリ使用量**（llama.cpp とモデルは取得しましたが、開発環境のポリシーにより外部取得したサーバー実行ファイルを起動できず、モック以外のLLM検証は未実施です）。手順は [docs/検証結果.md](docs/検証結果.md) の「実LLMの検証手順」を参照してください。
- Tesseract での実OCR（管理者権限が必要なため未導入）。
- ブラウザ内蔵PDFビューアでの表示・ページ移動（ヘッドレスのEdgeではPDFが描画されないため、画面確認はPDF以外の部分のみ）。
- 実在の（実際にスキャンした）契約書での精度。検証は架空サンプルのみです。
- Core i5 / 16GB 環境での処理時間（検証は Core Ultra 7 258V / 32GB）。
- Windows 10、マルチモニター、高DPI設定での表示。
